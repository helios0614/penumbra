# 长期工程原则

适用于 AionHome 与 Penumbra 的每次开发、修复、重构和验收。

**核心目标：保留必要防御，清理过度防御，让正常业务自然顺畅。**

- 防御必须有明确的保护对象和实际价值。
- 不以防御数量衡量代码质量。
- 低概率异常优先局部处理，不把异常成本转嫁给所有正常请求。
- 不为极少数异常让正常用户承担额外确认、等待、锁定、重复操作或页面限制。
- 避免错误状态、空白页面、错误提示和不自然的交互。
- 优先使用局部、可恢复、可诊断的处理方式。
- 已生成正文、已提交消息、已完成工具不能因为后续步骤失败而丢失或重复执行。
- 保留真正保护数据完整性、消息身份、执行一致性和资源安全的必要防御。
- 不随意新增全局锁、自动重试、超时、fallback、持久化队列和复杂状态机。
- 不因代码看起来重复就删除实际上保护不同生命周期的检查。
- 删除防御前必须确认原有保护对象已经由其他可靠机制覆盖。
- 每项新增防御都应说明保护对象、触发条件、正常路径成本及恢复方式。
- 测试必须同时验证正常路径和异常路径，不能只验证异常能否被拦截，还要验证正常交互没有变差。

## 实施前检查

在执行任何代码修改前，主动检查需求、方案和假设。发现需求存在歧义、方案可能无法达到目标、假设与源码不一致、存在更低风险或更合理的实现方式、修改范围可能影响已有业务，或解决方向可能只是表象而非根因时，先明确指出问题，说明原因、可能影响和推荐替代方案，不直接执行有问题的方案。仅属偏好差异时，可以说明后继续。

不得为了满足要求而默认认同错误前提。先固化合同测试，再修改实现；每次只修改一个明确边界，保留工作区已有改动。

## 最终目标

正常操作自然、顺畅；异常发生时能够准确识别、合理处理，并且不破坏已经完成的工作。
