# Chat UI 交互参考 & 实现备忘

来源：Ant Design X 官方文档及组件 Demo，提取交互模式供 Penumbra 自行实现。
不直接引入 Ant Design X，用 shadcn/ui + Tailwind 手搓，保持设计系统统一。

默认实现原则：
- P0 先保证稳定聊天闭环：消息展示、输入发送、停止生成、会话切换。
- 后端未就绪的能力先保留 UI 扩展点，不做假上传、假语音、假工具结果。
- 所有图标按钮必须有 tooltip 和 `aria-label`，键盘操作与触屏命中区域按 `docs/design-spec.md` 执行。

---

## 1. Bubble 消息气泡

### 交互要点
- 消息分 user / assistant 两种角色，左右布局（user 靠右，assistant 靠左）
- assistant 消息支持 **流式逐字渲染**，光标闪烁提示正在生成
- 消息体支持 Markdown（标题、列表、代码块、链接、图片）
- 代码块右上角有「复制」按钮
- 长消息可折叠/展开，默认阈值为 24 行或约 1200 字符，代码块不参与折叠高度计算时需保留独立滚动
- 每条消息底部有操作栏：复制、重新生成（assistant）、TTS 朗读
- 消息之间有时间分组标记（今天、昨天、更早）

### 实现方向
- 用 `react-markdown` + `remark-gfm` + `rehype-highlight` 渲染 Markdown
- 代码块用自定义 `<pre>` 组件，包裹复制按钮
- 流式渲染：维护一个 `streamingContent` state，SSE/WS 每收到 chunk 就 append
- 生成完成前显示 `▊` 光标闪烁动画
- 流式过程中使用容错 Markdown 渲染：未闭合代码围栏先按普通文本或临时代码块展示，最终消息完成后再做一次完整 Markdown 渲染
- 折叠按钮文案用「展开全文 / 收起」，并同步 `aria-expanded`

### 待解决
- [ ] 是否需要消息级编辑、引用回复、多选删除
- [ ] TTS 是否由浏览器 SpeechSynthesis 兜底，还是等待后端音频接口

## 2. Conversations 会话列表

### 交互要点
- 左侧栏展示所有会话，按时间倒序
- 每个会话显示：标题（自动截取前 24 字）、最后一条消息预览、时间
- 支持重命名、删除（hover 出现操作按钮）
- 当前会话高亮
- 新建会话按钮在顶部
- 移动端：会话列表作为侧滑抽屉
- 默认按时间分组：今天、昨天、近 7 天、更早

### 实现方向
- shadcn/ui `ScrollArea` + 自定义列表组件
- 移动端用 `Sheet`（侧滑面板）包裹会话列表
- 删除需要二次确认（shadcn/ui `AlertDialog`）
- 重命名桌面端优先 inline edit，移动端优先 `Dialog`

### 待解决
- [ ] 会话搜索、置顶、归档是否进入 P1
- [ ] 移动端是否需要边缘滑动手势；P0 先使用 Sheet 默认交互

## 3. Sender 消息输入区

### 交互要点
- 底部固定输入框，自动增高（textarea auto-resize，最大约 6 行）
- 支持附件上传的 UI 扩展点；后端接口未接入前，P0 只实现输入、发送、停止生成
- 发送按钮在输入框右侧，有内容时激活，无内容时禁用
- Shift+Enter 换行，Enter 发送（可配置）
- 发送后输入框清空并恢复最小高度
- 生成中显示「停止」按钮替代「发送」
- 输入法 composition 期间 Enter 不触发送，避免中文输入误发

### 实现方向
- `<textarea>` + auto-resize 逻辑（`scrollHeight` 赋值给 `height`）
- 附件预览条用横向 `flex` + 缩略图 + 删除按钮
- 发送/停止按钮用条件渲染，transition 切换图标
- 快捷键在 `onKeyDown` 里判断
- textarea 最大高度为 6 行，超过后内部滚动，不推动页面级滚动

### 待解决
- [ ] 附件上传接口默认预留 `/api/upload`，接入前发送按钮只提交文本
- [ ] 图片粘贴和拖拽上传进入附件能力一起做

## 4. ActivityTrail 活动流

### 交互要点
- assistant 回复前或回复中展示可公开的活动过程（如检索了哪些记忆、调用了什么工具、正在生成哪类结果）
- 以可折叠的时间线样式展示，每一步有标题 + 状态图标（进行中/完成/失败）
- 默认折叠，用户点击可展开查看详细内容
- 不展示模型隐藏推理或原始 chain-of-thought，只展示产品可解释事件和工具状态

### 实现方向
- 垂直时间线布局，左侧线条 + 节点图标，右侧内容
- 状态用语义色 token：muted=待执行、info=进行中、success=完成、error=失败
- 折叠用 `animate` + `max-height` 过渡

### 待解决
- [ ] 后端活动事件格式，建议 `{ id, title, status, detail?, timestamp }`
- [ ] 是否需要实时展示；P2 前先支持最终一次性展示

## 5. Suggestion 建议卡片

### 交互要点
- 对话开始或 AI 回复后，底部出现 2-4 个建议操作卡片
- 点击直接作为用户消息发送
- 横向滚动，移动端可滑动
- 只在合适时机出现，不是每轮都显示
- 用户开始输入、生成中、发生错误时隐藏建议

### 实现方向
- 横向 `flex` + `overflow-x-auto` + `snap-x`（CSS scroll snap）
- 卡片用 shadcn/ui `Card` 或自定义 pill 样式
- P1 初期前端按场景预设，后续再接 `/api/suggestions`

### 待解决
- [ ] 后端动态建议是否需要携带意图类型、图标、埋点 id
- [ ] 点击建议后是否立即发送；P1 默认立即发送

## 6. Welcome / Prompts 欢迎页

### 交互要点
- 新会话时显示欢迎界面，替代空白聊天区
- 展示 AI 角色头像、名称、简介
- 下方是 3-4 个固定 Prompt 快捷入口（「帮我写日记」「查看今天的日程」「回忆一下上周」）
- 点击快捷入口直接发送对应消息

### 实现方向
- 居中布局，头像用 `rounded-full` + 毛玻璃背景
- 快捷入口移动端用胶囊横滑，桌面端可用 2 列网格
- 点击后触发和普通消息一样的发送流程

### 待解决
- [ ] 快捷入口后续是否开放用户配置
- [ ] 是否根据时间/场景动态调整；P1 先固定列表

## 7. 附件与多模态

### 交互要点
- 输入框支持拖拽上传文件
- 图片附件在消息中内联展示（缩略图可点击放大）
- 视频附件显示播放器
- 文件附件显示文件名 + 大小 + 下载按钮
- 默认限制：单文件 20MB，单条消息最多 5 个附件

### 实现方向
- 拖拽：`onDragOver` + `onDrop` 处理，显示拖拽高亮区域
- 图片放大：shadcn/ui `Dialog` 或自定义 lightbox
- 文件卡片：icon + 文件名 + 大小的横向布局
- 支持类型先收敛到图片（png/jpg/webp/gif）、文本、PDF；视频进入后续迭代

### 待解决
- [ ] 后端上传、存储、病毒扫描与权限策略
- [ ] 附件预览失败时的 fallback 样式

## 实现优先级建议

| 优先级 | 组件 | 理由 |
|---|---|---|
| P0 | Bubble + Sender | 聊天核心，没有这两个没法跑 |
| P0 | Conversations | 多会话管理，基础功能 |
| P1 | Welcome / Prompts | 新用户体验 |
| P1 | Suggestion | 提升交互丰富度 |
| P2 | ActivityTrail | 需要后端配合，非阻塞 |
| P2 | 附件与多模态 | 锦上添花 |
